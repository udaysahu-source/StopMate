    Who can do what

    Student

    Anyone with the link. No sign in.

    • See the live bus and ETA
    • Pick My stop and get alerts
    • Cannot start, stop or change GPS

    Driver

    Added and approved by the admin. Signs in.

    • Start and end a trip on their own bus
    • Phone shares GPS only during a trip
    • Cannot add drivers or control other buses

    Admin

    You, for now.

    • Add, approve and remove drivers
    • Assign each driver to a bus
    • End any trip if something goes wrong

    Driver trip workflow

    flowchart TD
  A[Driver opens the driver page] --> B[Signs in with phone and PIN]
  B --> C{Registered and approved}
  C -- No --> D[Access denied and nothing to control]
  C -- Yes --> E[Presses Start trip]
  E --> F[Phone asks for location permission]
  F --> G[Phone sends GPS every 5 seconds]
  G --> H{Server checks the driver owns this bus}
  H -- No --> I[Update rejected]
  H -- Yes --> J[Students see the bus move live]
  J --> K{Reached college or End trip pressed}
  K -- No --> G
  K -- Yes --> L[Trip ends and GPS sharing stops]

    How the real app keeps students out

    The sign in on this page is only a demo of the screens. Hiding a button protects nothing, so in the real app the server makes every decision.

    • Roles live in a drivers table in the database: phone, name, assigned bus, and a status of pending, approved or removed.
    • Drivers sign in with Supabase Auth, using a phone code instead of the demo PIN. A student account has no row in the drivers table.
    • Row Level Security lets everyone read bus positions, but only the approved driver assigned to that bus can write a position or start or end its trip.
    • One active trip per bus. A second Start trip is refused while one is running.
    • The server ends the trip when a position lands within about 100 m of College. If no position arrives for 2 minutes, students see Bus offline.
    • Location is stored only during a trip. Removing a driver in the admin stops their access at once.
